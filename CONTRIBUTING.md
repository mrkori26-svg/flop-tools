# Contributing

FLOP Tools favors narrow, reproducible contributions over broad platform claims.

A useful contribution should do at least one of the following:

- provide a reproduction;
- provide an executable fixture;
- show a before/after protocol change;
- provide an adapter;
- validate another implementation;
- add retained CI evidence.

When discussing upstream protocol behavior, pin the source/version/commit and distinguish normative releases, open issues, provisional pull requests, target specifications and local policy.

Do not claim settlement, runtime compatibility, certification or external adoption without retained evidence supporting that exact claim.
